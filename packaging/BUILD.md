# 打包說明（給下一個發版的人）

## 一鍵發版腳本
- `python packaging/build_packages.py`
  自動編譯 `.lmo`、組裝 payload、執行 modefix、傳送 LXC 201 容器、簽名生成 `.apk` (x2) 與 `.ipk`、回傳至 `packages-<VERSION>/` 並執行校驗。

## 產線（PVE LXC 201 `apkbuild`，Alpine）
- `.apk`：`abuild -d`（`depends` 是 OpenWrt 套件名，Alpine 裝不到，一律 `-d` 跳過依賴檢查）
- `.ipk`：用 `ipkg-build-24.10` 建（官方 24.10 包就是 gzip 包 tar 容器：
  `./debian-binary`、`./data.tar.gz`、`./control.tar.gz`，跟官方逐欄對過）。
  血淚教訓：**絕對不要轉成 ar！**24.10 的 opkg 不吃 ar，轉了就是
  `Malformed package file`（2026-09-12 在公司 24.10 實證）。舊的 `ar_repack.py`
  已作廢，勿用。
- 執行位地雷三連（都踩過）：
  1. Windows 組 tarball 一律過 `modefix`（目錄 755／腳本 755／其餘 644；注意前綴比對別寫錯）
  2. `APKBUILD` 的 `package()` 用 `cp -a`（`cp -r` 吃掉執行位）
  3. 驗包看外層魔數：ipk 必須是 gzip（`1f 8b`），apk 解開腳本必須 755
- abuild 不給 root 跑：`builder` 用戶＋`PACKAGER_PRIVKEY` 指 key；`abuild checksum` 每次 payload 變都要重跑
- 同版重編必須升 `pkgrel`：opkg 認版本相同會跳過不安裝（apk 會重裝），2.1.5 實測公司機「up to date」跳過、被迫 `--force-reinstall`
- 簽名 key：`root-6aa40cae`，私鑰只在 LXC，公鑰隨包發布（`packages-1.1.0/*.rsa.pub`）

## 安裝（使用者側）
- 25.x（apk）：先信任公鑰或 `apk add --allow-untrusted *.apk`；主包＋`luci-i18n-geoguard-zh-tw`
  （語系包可不裝；英文即原始字串無需語系包）；語言跟 LuCI 系統走，conffile（`/etc/config/geoguard`、guard）會進
  `.apk-new` 不蓋掉現值
- 24.x（opkg）：`opkg install *.ipk`（容器／成員／control／755 已對官方包逐欄驗過；
  1.1.0-1 的 ar 版已下架作廢，勿傳）

## control 模板（opkg）
見 `luci-app-geoguard` Makefile 的 Depends/Description；`CONTROL/control` 由產線腳本生成，
改版記得同步 Version。

# Packaging notes (English)

## One-shot release script
- `python packaging/build_packages.py`
  builds `.lmo`, assembles the payload, applies modefix, ships it to the LXC 201
  container, signs `.apk` (x2) and `.ipk`, pulls them back to `packages-<VERSION>/` and verifies.

## Pipeline (PVE LXC 201 `apkbuild`, Alpine)
- `.apk`: `abuild -d` (`depends` are OpenWrt package names, uninstallable on Alpine, so always `-d` to skip the dependency check)
- `.ipk`: built with `ipkg-build-24.10` (stock 24.10 packages are gzip-wrapped tar containers:
  `./debian-binary`, `./data.tar.gz`, `./control.tar.gz`, matched field-by-field against official ones).
  Hard lesson: **never convert to ar!** 24.10's opkg rejects ar with
  `Malformed package file` (proven on the company 24.10 box, 2026-09-12). The old `ar_repack.py`
  is retired, do not use.
- The exec-bit triple trap (all stepped on before):
  1. Tarballs assembled on Windows must always pass `modefix` (dirs 755 / scripts 755 / rest 644; watch the prefix match)
  2. `APKBUILD`'s `package()` must use `cp -a` (`cp -r` eats exec bits)
  3. Verify by outer magic: ipk must be gzip (`1f 8b`), scripts unpacked from apk must be 755
- abuild refuses root: `builder` user + `PACKAGER_PRIVKEY` pointing at the key; rerun `abuild checksum` whenever the payload changes
- Signing key: `root-6aa40cae`, private key lives only in the LXC, pubkey ships with the packages (`packages-1.1.0/*.rsa.pub`)

## Install (user side)
- 25.x (apk): trust the pubkey first, or `apk add --allow-untrusted *.apk`; main package + `luci-i18n-geoguard-zh-tw`
  (language pack optional; English is the source language, no pack needed); language follows the LuCI system setting, conffiles (`/etc/config/geoguard`, guard) land in
  `.apk-new` without overwriting current values
- 24.x (opkg): `opkg install *.ipk` (container / members / control / 755 matched field-by-field against official packages;
  the ar-based 1.1.0-1 was pulled, never ship it)

## control template (opkg)
See Depends/Description in the `luci-app-geoguard` Makefile; `CONTROL/control` is generated by the pipeline script,
remember to sync Version on release bumps.
